# 首版范围与需求验收矩阵 — P0.8

- 版本：R1-scope-v1.1，2026-10-12（初版冻结 2026-10-09）（Asia/Shanghai）
- 授权依据：项目所有者明确要求继续完成 P0.7 到 P0.8，确认“采用这个范围”，并对组织、仓库、审批、会计和迁移参数授权“这个你直接确定下来”。以下是据此确定的发布设计，不是对真实公司现状的描述。
- 范围冻结仅确定要交付什么，不代表已经实现、生产 UAT 通过或允许部署。实施按 P0.9–P0.12 分包；发现原生缺口须提交证据并重新变更本版本。

## 冻结范围

单公司、人民币本位币及交易币种、简体中文操作界面、中文正式业务 PDF；主仓及分仓各一个，均归属同一公司。首版仅包括采购、库存、销售、退货、应收应付和七类原生报表，以及这些流程必要的主数据、权限审批、审计、迁移与运维控制。

七类报表固定为 Stock Balance、Stock Ledger、Purchase Analytics、Sales Analytics、Accounts Receivable、Accounts Payable、General Ledger。其它报表与仪表盘不构成首版验收要求。

不包含多公司、外币、制造/BOM、项目工时、完整 OA/HR、CRM 线索营销、费用报销、POS、网店、银行或法定开票自动集成、对外 Business API、MCP、Agent 或多 Agent。ERPNext 内部原生 API 用于配置/验证，不意味着交付独立 Business API 服务。

中文边界：冻结流程中的系统名称、字段、按钮、审批状态、系统活动、列表/明细、七类报表标题、十类交易打印正文须为简体中文。编码、内部键、网址、邮箱、代码示例、业务姓名及外部自由文本保留。英文历史业务内容不回写；已知词典标题和系统状态仅在展示端转换。受保护标准模板保留原属性；十类中文受控模板为业务默认。可选模块与非业务开发帮助不要求全站零英文，历史候选队列留作按缺陷处理的输入。

十类打印：报价、采购订单、采购收货、采购发票、销售订单、交货、销售发票、付款单、库存移动、库存盘点。正式 PDF 为 Must；HTML 预览不是 PDF 验收。英语兼容性为 Should，仅保留已测试的原生预览，不要求新增英语正式 PDF。

业务 PDF 是业务凭证输出；首版不交付法定税务发票签发服务。需要开票时由现有渠道办理，凭证编号通过原生附件/备注关联并纳入 SOP。

## 组织、财务和主数据基线

| 项目 | 冻结设计 | 实施/验收责任 |
|---|---|---|
| 公司/仓库 | 一个公司，一个主仓、一个分仓；关闭跨公司范围；仓库出入及跨仓调拨纳入原生库存核对 | ERP 管理员配置，库存负责人 UAT |
| 财务 | CNY，年度 1 月 1 日至 12 月 31 日，月度关账；原生权责发生制账务和永续库存；保留完整科目树，不伪造真实科目余额 | 财务负责人映射科目、核对期初和关账试验 |
| 税费 | 原生采购/销售税费模板；显式区分含税/未税报价；仅财务管理员维护税率、税科目及适用模板；不硬编码全公司统一税率，也不将无税模板静默套给实际应税单据 | 财务负责人以实际业务资料配置并完成含税/未税/退货 UAT；没有有效模板的需税场景不得上线 |
| 计量和价格 | 每物料唯一编码及库存 UOM；替代 UOM 明确换算；标准采购/销售价目表，价格由相应经理审核；无自动调价集成 | 采购/销售/库存负责人 |
| 编号与内容 | 原生独立单据编号序列，迁移旧编号存于原生外部引用/备注，不重命名系统键；中文名称由主数据负责人治理 | ERP 管理员及主数据负责人 |
| 往来/信用 | 财务维护客户信用额度与账期、供应商账期；首版不设未经验证的统一信用额度；无额度依据的赊销客户不放行 | 财务及销售负责人 |

这些参数是配置需求。真实公司名称、实名用户、科目、税率、账户、价格和余额仅保存在受控部署资料中，公开仓库保留合成样例。首版范围内已确定配置路径与责任；具体真实数据属于 P0.9 配置和 P0.12 UAT 输入，不能拿 P0 数据代替。

## 角色与审批矩阵

责任角色按职能确定，实名映射在 P0.9 建立；生产不得直接复用 Administrator 或测试账户。业务经理、财务复核人和业务负责人是独立审批身份。

| 单据/行为 | 录入/执行 | 审批规则（CNY） | 禁止事项与验收 |
|---|---|---|---|
| 采购订单 | 采购经办 | 含税总额 ≤ 10,000：采购经理；> 10,000：采购经理后由业务负责人复核 | 无自动批准；创建人不得审批自己的单据；测试 10,000 与 10,000.01 |
| 销售订单 | 销售经办 | 含税总额 ≤ 10,000：销售经理；> 10,000：销售经理后由业务负责人复核 | 同上；信用超限按原生规则阻断，不用审批绕过 |
| 收付款单 | 财务经办 | 全部由财务复核；绝对金额 > 20,000 再由业务负责人复核 | 制单与复核分离；测试 20,000 与 20,000.01、正负及撤销；实际银行支付继续人工 |
| 收货/发货/调拨 | 库存经办 | 来源已批准订单；收货/发货复核按库存负责人；跨仓调拨由库存负责人批准 | 仓库权限限制；无来源的非订单移动走库存负责人审批；原生是否支持按 P0.9 证据验证 |
| 盘点调整 | 库存经办 | 所有非零数量/金额调整由独立库存负责人复核，财务复核价值影响 | 不设自动放行的小额阈值；提交前附盘点依据 |
| 退货/贷项/撤销 | 相应经办 | 采购或销售经理核对原单，涉及账务由财务复核，全部留痕 | 不删除已提交记录，不通过回写数量伪装退货；测试库存/GL 冲回 |
| 主数据、配置与用户管理 | ERP 管理员 | 价格/税务/信用由职能负责人批准，权限配置由业务负责人批准 | 管理员不承担日常审批；紧急例外需审计并纳入 UAT |

原生 Workflow、角色组合和 User Permissions 优先。P0.6 仅证明合成角色及基础审批能力，尚未证明这里新增的分级阈值、全部库存/撤销动作和真实最小权限。实施包必须验证服务器端直接 API 操作也不能绕过；若原生配置无法满足，先记录最小缺口再变更范围，不能直接写 `hardware_erp`。

## 迁移范围与对账

迁移主数据（公司、仓库、科目、客户、供应商、物料/UOM、价目表及批准余额依据）、切换时点库存数量/价值、逐客户/供应商未结发票与付款分配、必要期初 GL 余额。原生导入/期初单据为优先路径，工具仅调用受审阅原生 API，不直接访问数据库。

已完成历史订单、交货、付款、聊天和附件不回灌；旧系统/受控档案只读保留，索引可从原生备注或附件链接查询。历史保留责任属业务负责人，禁止未经授权删除。未执行的旧订单不自动迁移；经业务核验后作为新批准订单建立并关联旧编号，避免重复记库存与 AR/AP。

迁移验收：唯一编码和外部引用无重复；每个物料×仓库数量差为 0；库存价值及 AR/AP 逐往来差 ≤ CNY 0.01，GL 借贷差为 0且与批准期初试算一致；任何舍入差必须有财务批准调整凭证，不静默容差放行。期初未结发票不得与期初 GL 重复计入，应收/应付控制科目与明细逐项一致。演练重复执行不新增重复交易；失败时明确停止、回退到隔离演练快照并重新对账。
