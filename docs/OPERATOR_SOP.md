# 首版操作 SOP — P0.9 / N4

版本 SOP-v1，2026-10-12；适用 R1-scope-v1.1 的单公司、两仓、人民币进销存。此文档依据本地合成技术演练编写，真实公司、实名职责、科目税率和期初余额由部署资料映射；员工培训及真实 UAT 在 A1 签核。本地测试账户不得迁入生产。

## 责任与每日入口

ERP 管理员维护主数据、用户及原生配置，不承担业务审批。采购/销售经办建立订单；采购/销售经理核对商业依据；库存经办办理收货、发货、调拨、盘点；库存复核人核对实物；财务经办建立发票、收付款；财务复核人核对账务；业务负责人复核超额订单/收付款。任何单据创建人与审批人必须分离，上级复核人与前一复核人也须分离，不因临时叠加角色而豁免。

每天检查登录身份、公司、仓库和日期；在原生列表按“待审批/待复核”筛选处理，打开来源单据及附件核对，再使用“操作”中的审批动作。每次动作后核实状态、活动记录与单据编号。没有待办清单中的条目不等于无未处理业务，应同时核对本部门原生单据列表。中文名称用于阅读，编码和系统编号作为追踪键。

## 主数据、计量、价格、信用及税费

由业务提交变更依据，经职能负责人批准后交 ERP 管理员配置。先搜索编码防止重复，再核对公司、两仓归属、物料库存单位、替代单位换算、价目表/有效日期、客户信用与付款条件。经办只能读取价格，不能修改价目表。

财务提供每类业务适用税模板、含税/未税方式和税科目。需税业务必须显式选择有效模板并核对净额、税额、总额及退货冲回；不得以空税模板代替尚未确定税率。N1 合成 5% 及 N2 无税边界样例只用于技术验收，不是实际税务政策。真实税率和需税场景的映射/签核是上线前门槛；系统无法凭空推断未标明的应税性质。无信用依据的赊销先暂停；信用超限不能通过经理审批或换客户绕过。

## 采购、收货和应付

1. 采购经办核对供应商、批准价格、数量、单位换算、需求日期、税模板和账期，保存采购订单草稿。草稿可由原经办修改。
2. 含税总额 ≤ 10,000 由采购经理“批准”；> 10,000 由采购经理“转负责人复核”，业务负责人“负责人批准”。10,000.01 不得走小额路径。
3. 库存经办从已批准采购订单创建采购入库单，按实际到货分批填写数量/仓库并附收货依据。库存复核人核对来源、已收累计、超收及单位后批准；不得从未批准订单收货。
4. 财务经办从收货建立采购发票，核对供应商账单、数量、价格、税额和未开票数量。采购经理“转财务复核”，财务复核人“财务批准”。确认应付来源和凭证。
5. 财务经办创建付款单，选择供应商、公司账户与原生发票分配金额；财务复核后人工办理银行支付并附银行凭证。系统审批不执行银行转账。部分付款保留逐发票未结余额，超分配先纠正。

## 销售、交货和应收

1. 销售经办从报价/商业依据建立销售订单，核对客户、信用、价格、税、账期、数量和交期。
2. 含税总额 ≤ 10,000 由销售经理批准，超额按经理→业务负责人两级审批。原生信用超限必须停止并由财务按批准依据维护信用，不能勾选绕过检查。
3. 库存经办从已批准订单建立交货单，核对实发数量与仓库；库存复核人批准。分批交货按每次实发建立来源链，不以修改已提交单据追加数量。
4. 财务经办从交货单建立销售发票，销售经理转财务复核，财务复核人批准。收款单采用 Receive，关联客户和发票分配；人工核对银行到账与未结余额。

## 库存、调拨和盘点

跨仓调拨使用原生库存移动 Material Transfer，填写来源/目标仓库和实物数量，由库存复核人批准，核对两仓数量与价值守恒。非订单入/出库使用对应库存移动类型，附原因，由库存复核人转财务复核后财务批准。权限必须覆盖两仓，禁止借用其它公司仓库。原生负库存阻断时先查日期、来源、实物及取消顺序，不关闭负库存控制。

盘点先导出截止时点库存余额，暂停受影响物料的实物移动，记录实盘和差异依据，创建库存盘点/调账单；数量是盘后余额，不是增减数量。库存复核人核实数量，财务复核价值影响。所有调整均需独立复核，无自动小额豁免。提交后核对物料×仓库数量、价值差及总账调整凭证。该类单据已启用原生版本追踪。

## 退货、贷项与撤销

退货从原交货/收货创建原生退货单，保留 return_against，负数量与实物退回相符。库存复核人“退货库存复核”→相应商业经理“业务复核”→财务复核人“财务批准”。财务经办从原发票建立贷项/借项，商业经理核对后财务批准；分别核对库存和 AR/AP/GL 冲回，不能只退实物不处理账款。

全交货后全退货会使订单 `per_delivered` 回到 0。这表示净交货为零，不能据此认定从未发货；必须查看原交货单、退货单和发票贷项链，由销售经理决定关闭/重发，禁止自动重复出库。

已提交单据不删除、不改价。库存/发票/盘点撤销由商业或库存负责人“申请撤销”→独立财务复核人“财务撤销”；订单/收付款由各自复核角色执行“撤销”。先取消下游及退货/贷项，再取消原发票、实物单据和订单。若退货曾补回库存，取消该退货前须确保其库存不会已经被另一退货消耗；本次演练实际遇到原生负库存阻断，并依赖逆序恢复，未降低控制。

收付款金额不录入负数；退款使用对应 Pay/Receive 类型与正金额，冲回使用原单撤销或原生贷项链。所有收付款均由财务复核，金额 > 20,000 再由独立业务负责人批准。实际支付/到账以受控银行凭证核对。

## 审批异常与审计

草稿由经办修改；进入中间复核阶段后不得改价、税费或数量。复核发现问题时使用“退回重填”，由经办修正后重新走全审批链。服务器拒绝直接 submit/cancel、同请求改价审批、创建人审批和越权角色；错误不能靠切换 Administrator 或客户端脚本绕过。管理员仅处理配置、核对错误及恢复，不代替常规审批。

每日保存审批依据索引，核对活动中的操作者/时间/动作、版本与原单编号；普通经办不能删版本/审批记录。配置及权限变更须记录批准人、变更内容、验证结果和回退依据，管理员账号仅紧急受控使用。不要将姓名、凭证、备份或登录信息提交到公开仓库。

## 七类报表与日/月对账

| 职能 | 原生报表 | 核对 |
|---|---|---|
| 库存复核 | 库存余额、物料凭证 | 同公司、同日期、同仓库；数量/价值到来源收发/调拨/盘点 |
| 采购经理 | 采购统计分析 | 选择订单口径、供应商/物料、数量/金额及期间；取消单据与正式交易区别 |
| 销售经理 | 销售统计分析 | 订单口径与交货/发票口径不混算，核对全退货净状态 |
| 财务复核 | 应收账款、应付账款、总账 | 账龄截止日、逐客户/供应商及发票分配；查看撤销分录和净额 |

每日核对未收货/未交货/未开票、未分配收付款、库存差异和审批中单据。月末确定截止时点，清理异常、完成库存与 AR/AP 逐项对账、核对控制科目与明细及 GL 借贷平衡。差异须追到单据，不能用无依据的调整抹平。财务批准后通过原生会计设置/期间限制冻结截止日，在隔离演练验证跨期/撤销拒绝；真实关账及恢复演练归 A1，不因这份 SOP 而视为已通过。反关账需受控批准、审计及重新对账。

## 中文正式 PDF 与法定开票引用

打开已批准单据→打印→该类“（简体中文）”受控模板→PDF。核对公司、供应商/客户、编号、日期、仓库、数量、价格、税、合计、币种和原单，确认无截断/缺字后存受控档案。打印的是业务凭证，不是法定税务发票；人工开票渠道办理后，通过原生附件/备注关联法定凭证编号并核对金额。原生英语 HTML 预览继续保留，正式中文 PDF 为首版输出。

## 日常运维与故障恢复

本地启动按 `scripts/phase0-start.sh`，其固定镜像包含中文展示、字体和独立审批守卫，安装 app、设置内部打印地址、清缓存并执行健康检查；配置按 N1→N2→N3 重放，脚本默认只读，合成写入需要显式参数。重连后先读 handoff、检查 Docker 与健康，再验证配置，禁止直接删数据卷重新初始化。

遇到 502、PDF 资源失败或实时失联，先停止相关操作，保存脱敏错误/时点、检查服务日志和固定镜像版本；使用内部 Docker 地址解决打印资源，不放开公网端口或来源检查。当前运行只允许固定本机来源，正式域名的反向代理与 TLS 属部署配置。维护重启后重验健康、登录、实时、PDF 与权限，再恢复录入。

备份由受控部署运维人使用原生 bench 备份与文件备份命令，备份目录在私有访问边界内；记录版本、文件完整性、备份时点和加密/访问责任。恢复只在隔离环境先演练，按批准备份恢复数据库与公开/私有文件、匹配 app 版本并执行原生 migrate；Agent 不执行 SQL 或访问 ERP 数据库。随后逐仓库存、AR/AP、GL、权限、审批、PDF、实时核对到同一截止日。完整站点恢复及旧版本回退尚属 A1，未通过不能部署。

审批守卫不可直接卸载后继续营业：先停止写入、撤回候选版本，在隔离副本恢复前一完整版本并验证原生审批缺口不会进入生产。P0 discovery 公司是可弃测试例外，真实发布预检必须移除 P0 数据及账号，禁止把该名称用于绕过审批。保留取消记录/版本，不清理为“无痕通过”。

## 本次技术演练与交接

N2 原生 API 已执行订单两级审批→收货/发票→交货/发票→双方退货及贷项→调拨/盘点→依赖逆序取消，库存和逐科目 GL 归零；审批退回后重审已执行。参见 `phase0/evidence/n2-access-runtime.json` 的合成单据/活动记录。该技术演练不是实名员工培训、真实税务验收、迁移或生产恢复。A1 各职能须照本 SOP 完成现场操作、错误处理和中文 PDF 检查并签核。

首版技术环境已通过原生 System Settings 关闭自动入门指南（enable_onboarding=0），避免窄屏遮挡业务字段。需要培训引导时可由管理员按培训计划重新开启；关闭引导不改变权限或审批。已撤销的合成审批记录可能显示原生 Workflow 的“拒绝”状态，应以单据 docstatus=2、版本与撤销链确认，不能据此重复执行原交易。
