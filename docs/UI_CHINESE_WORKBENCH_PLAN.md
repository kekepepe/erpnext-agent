# 中文业务工作台与术语改造计划

日期：2026-10-27。状态：已按用户要求纳入计划，未实施、未验收。本轮只编制计划；后续统一执行。此计划不代表重建 ERP、增加业务模块或部署授权。

## 目标与方案

用户要求采用国内进销存的操作习惯：左侧固定业务大类，右侧展示业务内容；中文用词来自国内 ERP 的真实业务场景，不再以英文逐词翻译为主要依据。

建议保留 ERPNext 后端、单据模型、权限、审批守卫、库存和账务逻辑，在当前仓库内实现可停用的独立展示模块。优先使用原生 Workspace/侧栏配置及前端扩展。全局导航跨路由兼容性须先验证；不预先承诺仅靠 CSS 完成。不新建独立全栈项目，不重写整套交易前端，不用 iframe 拼接页面。模块具体归属在技术验证后确定，不能把业务守卫与界面代码混为一体，也不能将现有翻译补丁授权扩大为任意 Core 修改。

## U0：国内 ERP 参考与现状盘点

- [ ] 以网上管家婆进销存（当前五金工业演示帐套）为操作结构主参考，以金蝶精斗云/云进销存为术语和流程交叉参考。记录具体产品、版本或页面日期，避免把不同金蝶产品的叫法当作同一套规范。
- [ ] 逐项研究：首页、一级/二级导航、采购、销售、库存、收付款、基础资料、七类报表，以及列表、详情、审批状态、提示和打印。仅查看演示与官方帮助；不在外部演示账套创建业务数据。
- [ ] 为每个结论保留官方链接、查看日期、相关短摘录或脱敏截图索引。借鉴结构和业务表达，不复制品牌、商标、素材或私有代码。
- [ ] 盘点当前对应页面和中文词典/展示扩展/打印模板，区分英文遗漏、翻译生硬、业务含义不准、同义词不一致及导航问题，形成问题清单。

## U1：建立中文业务术语规范

- [ ] 建立版本化词表：内部 DocType/字段/状态键、当前显示、业务定义、国内产品用词及来源、建议显示、适用上下文、不能混用的词、确认状态和使用位置。
- [ ] 覆盖菜单、单据标题、字段、表格列、按钮、筛选、状态、系统错误/提示、七类报表、十类 PDF 和 SOP；同一业务概念保持一致。
- [ ] 为五金贸易选定一套主用语，例如“商品/物料”“采购/购货”“供应商/供货单位”，保留搜索同义词方案；不把多个厂商叫法机械混用。
- [ ] 高风险词按实际行为核对：提交不一定等于审核；取消不一定等于作废；撤销、反审核、红冲不能互换；可用库存与实际库存不同；应收应付与收付款不同。
- [ ] Purchase/Sales Invoice 的展示名称必须结合当前记账和库存选项确定，明确不是法定开票服务；入库/出库与应付/应收确认不能仅靠改名合并。
- [ ] 退货区分实物退回、账务冲减及退款。Payment Entry 根据收/付/内部转账语义显示，Stock Entry 根据用途显示；不得全局一词替换。
- [ ] 保存内部标识、接口键、单据编号、审计原值及用户自由输入，仅改变受控展示；术语变更不回写历史业务文本。搜索、报表导出、错误信息和 PDF 的覆盖边界逐项记录。

以下仅为候选映射，须经 U0/U1 语义核验：

| 现有对象 | 候选展示 | 必须核对 |
|---|---|---|
| Item | 商品／商品档案 | 五金主数据、编码、规格、单位语境 |
| Purchase Receipt | 采购入库单 | 退货及库存/账务实际效果 |
| Delivery Note | 销售出库单 | 发货、退货、关联订单及库存效果 |
| Stock Entry | 库存业务单，按用途区分 | 调拨、其他入库、其他出库不混淆 |
| Stock Reconciliation | 库存盘点调整单 | 不把原生调整单冒充完整实盘任务流程 |
| Accounts Receivable / Payable | 应收账款／应付账款 | 报表含义、未结金额与账龄 |

U1 交付：术语表、冲突处理记录、术语使用规则。退出条件：全部首版显示面可追溯；涉及库存、记账和审核含义的歧义已解决，需业务/财务确认的项有明确责任人，不能静默选词。

## U2：信息架构与可点击原型

- [ ] 左侧约 180–200px 固定导航：工作台、基础资料、采购、销售、库存、收付款、报表；系统设置置底。按角色显示有权使用的入口；隐藏入口不能替代服务端权限。
- [ ] 当前大类展开子菜单，列表和单据详情保留选中状态；提供面包屑、返回列表、最近访问。管理员保留完整原生管理入口。
- [ ] 工作台优先常用操作、待办和最近单据；数值定义、日期范围和权限明确，不引入新经营报表承诺。原型模拟数据显式标注。
- [ ] 右侧统一列表筛选、主要按钮、紧凑表格、合计和分页；详情页优先常用字段，低频内容折叠但不遮蔽必填错误。
- [ ] 使用自有视觉样式：深蓝侧栏、浅灰背景、白色内容区、清晰选中状态；兼顾键盘、焦点、文字对比度及小屏抽屉导航。
- [ ] 至少交付工作台、采购订单列表、采购订单详情三个相连原型，并补充销售/库存/收付款/报表的导航映射。原型使用 U1 术语。
- [ ] 第一版不承诺多页签同时编辑；如后续纳入，先验证未保存内容、关闭提醒、状态隔离及浏览器历史，再单独估算。

U2 退出条件：可走通“选大类→找单→查看/新建→返回”的路径；用户可审阅原型和术语；不能只有静态首页。

## U3：真实系统最小接入与扩展

- [ ] 先做采购链试点：导航壳+原生列表/表单/报表路由。验证原生侧栏配置能满足的部分，再补最小扩展，避免持续 DOM 扫描/脆弱选择器覆盖。
- [ ] 验证刷新深链接、浏览器前进/后退、返回筛选与分页、未保存提醒、会话过期、弹窗、表格编辑、打印和实时通知。
- [ ] UI 与翻译独立可停用，能回到原生界面；固定资源构建、依赖及版本。安装/迁移/重放/停用/恢复必须纳入生命周期验证。
- [ ] 试点通过后覆盖其余首版模块、七类报表、十类 PDF 和帮助/SOP；不借菜单改造增加制造、网店等业务范围。
- [ ] 实施前在范围文件中登记展示范围修订和验收项，确定应用归属；本计划不直接改写 R1-scope-v1.1 为已交付新版本。

## U4：验收与发布衔接

- [ ] 对照词表检查各页面/报表/PDF/SOP，覆盖上下文词义、漏译、截断和同义词冲突；逐页视觉审阅十类 PDF。
- [ ] 按采购、销售、库存、财务、审批、管理员分别验证可见菜单与权限；直接 URL/API 越权仍被拒绝，原有审批守卫与业务结果不变。
- [ ] 回归采购到付款、销售到收款、退货、调拨/盘点、应收应付/总账、审批与审计；不把 UI 展示通过当作账务验证通过。
- [ ] 检查 1280×720 与 390×844，表格横向滚动、可操作性、键盘焦点、报错定位及网络/加载状态。
- [ ] 邀请实际职能人员按熟悉的业务说法找功能、开单、查账；记录误解、错选和绕路，修订词表、原型和 SOP。技术验证不替代职能 UAT。

U4 退出条件：全部范围内页面有术语和行为验收记录，无阻断缺陷；UI 可回退，升级/资源漂移有检查，验收结果纳入不可变 RC。

## 执行顺序与本轮边界

本轮仅形成计划及交接。后续安排：U0/U1 研究和 U2 原型可在实现前准备；先完成现有 C0 基线验收，再执行 U3。涉及迁移字段名称的 M1 模板使用 U1 已确认名称和稳定内部键；最终顺序为 UI 实施完成→受影响 C0 重验→M1 两轮迁移→A1 综合 UAT/恢复/RC→明确批准后进入 Phase 1。

旧 P0.9 技术验收保留为历史基线，不声称覆盖新 UI。不改变库存/账务逻辑、不增加法定开票、外部集成、Business API、MCP 或 Agent。提交与推送仍需用户明确要求。
