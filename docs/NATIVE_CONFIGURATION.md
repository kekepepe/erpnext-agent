# 原生配置基线 — P0.9 / N1

## 2026-10-09 已实现的合成技术基线

`phase0/release-baseline.json` 与 `scripts/phase0-configure-release.py` 只操作本机一次性站点的 `R1合成发布验证公司`（R1D）。它是首版配置路径的技术样例，不是实际企业名称、财务参数或生产部署。原 P0 公司、用户权限、全局默认项、编号序列及已提交交易不回写。

| 配置 | 实际验证值 | 生产映射/验收边界 |
|---|---|---|
| 公司/币种/库存会计 | R1D、CNY、永续库存、Moving Average | 真实公司标识和会计口径由财务负责人在受控资料映射，P0.12签核 |
| 仓库 | `R1测试主仓 - R1D`、`R1测试分仓 - R1D`；自动创建的额外空叶子仓禁用但不删除 | 原生库存台账确认额外仓无分录才禁用；生产命名/地址/权限另映射 |
| 财年/科目 | 复用只读 `2026`，2026-01-01至12-31；96个原生科目（含合成税费科目）；AR/AP及库存过账默认科目存在 | 标准树不是已接受的实际财务科目映射；期初 GL与税科目须由财务负责人逐项核对 |
| 税模板 | 采购/销售各含税与未税四个模板，全部 `is_default=0` | 5%只是合成算术，不能用于真实业务；生产采用财务批准的明确税模板，实际需税性质与有效模板映射/拒绝验收是财务 A1 门槛；N2 无税阈值样例不冒充此验收 |
| 主数据 | 一个独立合成客户、供应商、客户叶子组、物料组及中文物料名称 | 生产客户/供应商/物料等由主数据负责人治理，不收录于公开仓库 |
| UOM/价格 | 库存单位 Piece；Box=50 Piece；独立CNY采购价60/销售价100 | 合成价格，不是报价；生产由采购/销售经理审核 |
| 信用/账期 | 合成客户额度1000、不绕过信用校验；30天账期 | 合成默认仅用于后续负向验证；真实额度/账期按受控名单配置 |
| 编号 | 原生编号，无全局系列修改；合成草稿生成原生编号 | 真实系列在 native Naming Series/各 DocType原生配置中登记；旧来源编号只作外部引用；重放不得碰已提交编号 |

脚本默认只读，缺失配置退出1；显式 `--apply` 才创建合成配置。发现现有公司币种、UOM、价格、模板或账期冲突时停止，不覆盖。拒绝远程/生产URL及其它公司命名空间。中断后重跑只复用相符配置，不清空数据库、不删除记录、不提交业务交易。

```sh
./scripts/phase0-check.sh
.venv/bin/python scripts/phase0-configure-release.py --apply
.venv/bin/python scripts/phase0-configure-release.py
.venv/bin/python scripts/phase0-validate-release.py --create-drafts
.venv/bin/python scripts/phase0-validate-release.py
```

税验证器在该合成公司创建/复用四张草稿：采购订单未税/含税，销售报价未税/含税。含税输入105、未税输入100，原生均得净额100、合成税费5、总额105；四张税样例 docstatus为0；N2 后保留取消的 GL/库存历史，验证器改为检查逐科目净余额和两仓库存数量/价值为零。默认只读；匹配签名重复、状态或项目金额冲突立即失败。它不证明真实税模板、退货税冲回或信用拦截已经 UAT。

原生首次客户插入拒绝根节点 `All Customer Groups`；增加独立叶子组后续跑成功，已有配置保留。两次只读配置复验、两次税复验应各自stdout一致，无新增草稿；新增安全检查覆盖禁止非合成命名空间、现存币种冲突不覆盖、只读缺失不写入。

## 受控生产参数映射流程

1. ERP管理员与财务负责人在受控资料记录公司、会计年度/结账规则、科目对应及税模板；库存负责人登记主仓/分仓及权限。公开仓库只存此流程和合成样例。
2. 通过原生 Company、Fiscal Year、Account、Warehouse、Tax Template、UOM、Item、Customer/Supplier、Payment Terms、Price List/Item Price及Naming Series界面/审核后的API配置，不直接SQL操作。不得把R1/P0测试公司或测试用户迁成生产实体。
3. 财务复核收/付款、库存资产/暂估、收入/成本/盘点调整及税科目映射；明示含税/未税、币种、精度、合法业务模板。未映射或未审批的需税流程不放行。
4. 主数据负责人核对中文名称、唯一编码、替代UOM、单位价格、信用额度、账期和外部引用。价格/税率/信用维护权限及提交阻断按N2的服务器端权限/Workflow负向验证收紧。
5. 在隔离生产样式环境用批准的预期结果验证含税/未税/折扣/退货、库存/账务、账期与信用、关账及编号防重。P0.12完成真实角色UAT和财务签核；不能用本次合成通过替代。

此包完成可重放的原生配置技术基线，R1-01–05的真实参数映射、业务控制和最终UAT仍按N2/N4/M1/A1验收。下一包为N2：先原生实现订单/付款分级审批及制单复核分离，再扩展库存、退货和撤销控制；发现原生无法满足的证据后才变更范围。
