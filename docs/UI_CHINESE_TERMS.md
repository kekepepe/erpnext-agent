## 4. 状态与动作：按当前代码解释，不按英文直译

依据 L1。文档实例字段为 `docstatus`；工作流配置状态表中的属性为 `doc_status`，二者不能混写。审批状态与履约进度分成两栏。

| 内部状态/条件 | U2 展示 | 语义与限制 |
|---|---|---|
| 新建未保存 | 未保存 | 前端编辑状态，不伪造服务器工作流状态 |
| docstatus=0，workflow_state=Pending | 待审批（未生效） | 当前初始状态即 Pending；不能凭空添加“提交审批”转换 |
| 待负责人复核，docstatus=0 | 待负责人复核 | 已有中间状态，未生效 |
| 待业务经理复核/待财务复核，docstatus=0 | 保留中文状态 | 适用于对应单据，不把它们套到全部采购订单 |
| Approved，docstatus=1 | 已批准 | 已生效，不代表入库/付款完成 |
| 待财务撤销复核，docstatus=1 | 待撤销复核（仍生效） | 撤销尚未完成 |
| Rejected，docstatus=2，当前 R1 工作流 | 已撤销 | 实际来自撤销/财务撤销，不显示“已驳回” |
| 中间复核态→退回重填→Pending | 待审批；活动记录“退回重填” | 仍是未生效单据；现有状态不能单独识别“待修改”，须依审计说明 |
| 原生 Cancelled，docstatus=2 | 已撤销 | 仅受控范围内统一；不能据此全局替换对话框 Cancel |
| 原生订单 status/per_received | 执行状态/入库进度 | 原生关闭、暂停、退货净状态保留；不能仅凭百分比覆盖全部状态 |

采购订单原型动作矩阵（来自 L1；资格还受公司、权限、创建人、自审批守卫及后续单据约束）：

| 当前情况 | 角色 | 显示操作 | 结果 |
|---|---|---|---|
| 新建或 Pending | 采购经办 | 保存、返回列表 | 保存仍未生效；不展示一个不存在的独立“提交审批”动作 |
| Pending，含税总额≤10,000 | 独立采购经理 | 批准 | Approved / docstatus=1 |
| Pending，含税总额>10,000 | 独立采购经理 | 转负责人复核 | 中间状态，不生效 |
| 待负责人复核，金额>10,000 | 独立业务负责人 | 负责人批准、退回重填 | 前者生效；后者回 Pending |
| Approved | 独立采购经理 | 撤销 | 服务端检查依赖后才能进入已撤销；有下游单据不承诺成功 |
| 已批准且可收货 | 有权限的库存经办 | 生成采购入库单 | 创建关联草稿，不自动提交或记账；U3 验证原生映射条件 |
| Rejected/docstatus=2 | 有原生修订权限者 | 修订（候选入口） | 待在线验证，不做“恢复原单生效”按钮 |

普通采购经办不显示审批按钮；制单人与审批人重合时，即使拥有多角色也不能批准。Pending 目前没有“驳回”转换，不为原型新增该按钮。管理员不充当日常审批人。列表返回保留筛选、页码及滚动位置。

## 5. 高风险业务口径

1. 保存、批准、撤销是不同操作；取消弹窗只关闭操作，离开未保存页面提示“放弃未保存的修改”。不将任何厂商的“审核”概括为本系统提交与审批的同义词。
2. 库存：`actual_qty` 暂称“现存量”（账面数量，不宣称已实盘）；`projected_qty` 称“预计库存”。E2 描述的计划/请求/订购/预留参与预计量，不能改称“可立即出库数量”。“可用量”没有批准字段和预留规则前不进入原型数值卡片。
3. 应收/应付未结金额采用原生未结字段/报表结果；预收预付、已分配/未分配款、退货贷项、核销与调整均须考虑，不在前端以发票总额减收付款总额自行计算。
4. 企业视角的资金方向（E4）：客户正常付款到企业是 Receive；企业退给客户是 Pay；企业正常付供应商是 Pay；收到供应商退款是 Receive。分别显示“收款单/付款单”并附业务用途，不能仅凭负数金额或往来类型判断退款。
5. 退货分别说明实物、账务、资金效果。Credit Note 是销售侧概念；采购退货账务单不能一律套同名。ERPNext 原生允许部分组合流程，例如带 Update Stock 的销售退货发票；展示层不得新增合并/拆分交易行为，也不能重复记库存。
6. Invoice 暂保留采购/销售发票，副注“用于记录采购应付/销售应收，本系统不办理税务开票”；最终名称与库存更新选项由业务/财务核对。红字发票、红冲、反审核不作泛化替换。
7. 单价字段 `rate` 不直接标为“含税单价”或“未税单价”；依据税模板确认。净额、税费、含税总额、舍入后金额分开，显示精度沿用原生规则；数量跨单位不直接相加。

### 6.3 交互提示与原型场景

| 场景 | 建议文案/行为 |
|---|---|
| 空列表 | 暂无符合条件的采购订单；可重置筛选 |
| 必填遗漏 | 请选择供应商／请添加商品；错误定位到具体字段（实际必填以元数据为准） |
| 未保存离开 | 有尚未保存的修改。继续编辑／放弃修改 |
| 权限不足 | 无权执行此操作，请联系管理员；不暴露无权查看的单据内容 |
| 自审批被拒绝 | 制单人不能审批自己的单据，请由独立审批人处理 |
| 保存成功 | 已保存，尚未生效；显示当前审批状态 |
| 网络失败/超时 | 未确认操作结果，请刷新核对；不自动重复提交 |
| 撤销 | 确认撤销该单据？后续关联业务可能需要先处理；不承诺所有单据都产生账务冲销 |

最小原型场景：采购经办新建→保存待审批→经理批准低额订单；高额转负责人→批准或退回重填；已批准部分入库；已撤销只读；无结果、必填错误、未保存返回、无权限。使用不同模拟身份，不能在同一制单人身份下演示自审批成功。U2 无真实写入。
