# 完整中文业务工作台实施计划

2026-10-28。用户要求由 U2 原型进入全部首版组件的前后端完善；本计划是实施范围和验收清单，不是完成声明。沿用 UI_CHINESE_WORKBENCH_PLAN、U1 v0.2 与 R1 业务边界。

## 方案与完成定义

在当前 erpnext_zh 展示扩展中增加独立 workbench 模块；hardware_erp 负责审批守卫及 DEC-014 已批准的交易信息扩展。不新建独立 ERP 后端、不改变库存会计规则、不增加业务 Core 补丁。工作台和导航使用统一中文界面，具体列表、表单、关联单据生成、审批、打印及报表使用真实原生组件；原型8092保留作对照，正式开发入口为隔离的本地 ERP 环境。

“全部”指下表首版业务，不包括 ERPNext 自带但不在首版的制造、HR、网店等。菜单必须有真实目的地，不能只显示占位说明。服务端提供受权限约束的导航和只读工作台数据，写操作全部使用原生接口及守卫。没有建立新的独立 Business API 产品。

| 模块 | 必须接通的组件 | 原生对象 |
|---|---|---|
| 工作台 | 常用入口、当前身份、待审批入口、近期修改单据、加载/失败/空状态 | 原生 Workflow Action、权限过滤的列表 |
| 基础资料 | 商品/分类、客户、供应商、仓库、计量单位、商品价格、价目表 | Item/Item Group/Customer/Supplier/Warehouse/UOM/Item Price/Price List |
| 采购 | 订单、入库、采购发票、实物退货、退货账务；关联原单办理 | Purchase Order/Receipt/Invoice，is_return筛选 |
| 销售 | 报价、订单、出库、销售发票、实物退货、贷项 | Quotation/Sales Order/Delivery Note/Sales Invoice |
| 库存 | 调拨、其他出入库、盘点调整、余额及流水 | Stock Entry按purpose筛选、Stock Reconciliation、原生报表 |
| 收付款 | 收款、付款、资金转账、应收应付查询 | Payment Entry按payment_type筛选、原生报表 |
| 报表 | 库存余额/流水、采购/销售分析、应收/应付、总账 | 原生七类Query Report |
| 设置 | 有权限的配置入口与返回原生Desk | Company/Workflow/User/Role/System Settings |

所有入口按当前会话权限生成，不允许 UI 角色模拟切换进入真实系统。公司/仓库权限与直接 URL/API 访问仍由 ERPNext 决定。退货列表不允许误导性新建普通单据，必须从原单生成。业务管理员权限不是普通角色验收的替代品。

## 实施包

- [x] W0 基线：恢复环境，记录版本和现有服务；检查C0最后修复与独立生命周期环境。保留已有卷，不为方便验证清空用户数据。
- [x] W1 后端：统一菜单目录、允许项计算、公司与文档权限过滤、只读近期单据、原生待办入口；guest拒绝、受限角色测试、无跨用户缓存。
- [x] W2 前端框架：固定大类/展开子类、原生路由、当前状态、手机抽屉、原生回退开关；不使用iframe或重写原生Form生命周期。
- [x] W3 业务接入：覆盖上表入口，列表/详情/关联单据/审批/打印/报告沿用原生；重复doctype的不同筛选必须可重置且正确高亮。
- [ ] W4 术语与错误：仅受控标题/菜单和已核验上下文，不对用户内容做全文替换；Invoice/退款/撤销按U1语义，保留未确认财务标题说明。
- [x] W5 验证：离线目录/权限单测，真实API角色边界，登录后浏览器导航、表单/列表/报表、刷新/返回/未保存提醒及双尺寸检查。
- [ ] W6 发布门槛：完整C0安装/迁移/卸载重装与两轮业务回归，扩展启停/回退；输出/实时、M1迁移和A1完整UAT/恢复/RC后才允许Phase1。

用户本次指令授权现在开始前后端实现，更新此前“仅原型、U3未授权”的状态。W1-W4可在隔离开发环境推进，但C0未验收不得称为可发布，W6不跳过。每轮交接必须分开列出已写代码、已在线验证、尚未验证，不以菜单可点替代业务验收。
