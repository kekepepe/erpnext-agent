# 本地 ERP 功能补齐计划

本计划以[管家婆功能差距](GUANJIAPO_ERP_GAP_ANALYSIS.md)为输入，适用于本地 Phase 0 测试站。执行顺序为 **报价与录单 → 出入库与结算 → 物流与成本 → 查询、迁移和发布验证**。首个开发批次保留已实现的五档价格、客户默认档位、商品双语资料及原生单据关系。首批执行进度见文末，后续批次按下表推进。正式上线仍以首版范围和发布验收为准。管家婆继续作为只读参考。

## 1. 先确定验收样例

利用合成客户、供应商、商品和两座仓库，建立一份采购及销售共用的验收样例。报价样例记录商品、计量单位、可用价格来源、预期来源、单价、折扣和含税总额。结算样例记录起始余额，以及在下单、收发货、发票、收付款和退货各步骤后的库存、存货金额、应收应付及已收已付。

采购、销售分别确认专价、历史成交价、档位价、商品默认价的取值顺序，确认数量阶梯与整单折扣能否叠加，以及订单确认、收发货改价、退货是否纳入历史取价。财务确认折扣基准、尾差、应收应付确认时点、预收预付及运费入成本口径。实际规则待确认期间，可用带明确预期的合成规则验证技术路径，继续做录单预览和入口串接。

## 2. 分批实施

| 批次 | 待补功能及实施方式 | 验收标准 | 责任岗位、依赖 |
|---|---|---|---|
| 1A 报价取价 | 验证原生商品价格、客户/供应商专价和价格规则，配置数量、有效期及优先级。明确历史价来源和回退顺序，原生配置无法覆盖时再补最小规则扩展。单据显示建议价及来源，保留已授权人工改价和审计入口。最低售价先确认采用提示还是拦截。 | 同一商品分别验证客户和供应商匹配、规则冲突、过期、无价、不同单位、数量临界点及改价权限。选中来源和金额与样例一致。改动商品价目表后，已保存历史单据价格保持原口径。 | 采购、销售、ERP 管理员。真实取价口径依赖第 1 节。 |
| 1B 录单核对 | 报价、采购及销售订单和收发货页在编辑时显示逐行折后价、含税值及整单合计。预览复用原生计算链，增加保存前后核对。梳理扫码、批量商品导入、常用字段和客户/供应商默认值。 | 修改数量、单位、行折扣、整单折扣或税模板后，草稿预览与服务端保存结果逐行、逐单一致到分。验证含税输入、未税输入、退货负数、跨行尾差、空税模板和未配置单位。导入能指出错误行，使用有效数据重试后行项目无重复。 | 采购、销售、财务。可与 1A 并行，以现有档位价做测试。 |
| 2A 询报价与来源 | 用原生询价请求、供应商报价、销售报价及单据关联能力，补充询价到采购订单及销售报价到销售订单的工作台入口。提供按已批准原单收发货及查看待收发数量的入口。 | 由询报价生成订单后，供应商/客户、商品、单位、来源和审核状态可追溯。分批收发只带剩余数量。未批准、已关闭或越权访问的原单不能生成后续单据。 | 采购、销售、库存。优先走原生映射。 |
| 2B 出入库与结算 | 在收发货详情集中展示来源订单、发票、收付款和待处理金额，提供前往关联单据办理的入口。可试验本单金额、此前未结、预收预付可用额的同屏查询。若业务确认需要一次操作串联多张单据，再验证原生审批、失败恢复和防重复写入。 | 跑通现结、赊账、部分付款、预收预付核销、分批和退货。按原始发票核销，账款分配和余额正确。实物退货、贷项/借项及实际退款均能回到原单。重复操作不重复记账，待审批及反向冲回路径可用。 | 财务、库存、采购、销售。依赖第 1 节的结算口径和 2A 的单据关系。 |
| 3 物流、运费与成本 | 优先试用原生运输规则、货运单和到岸成本凭证。补物流公司、运单和运费关联入口，区分买家运费、供应商运费、入成本费用与实际付款。财务对比移动平均与旧系统成本样例，形成差异表。 | 用两种商品、一笔运费验证分摊总额、存货价值和凭证对应。费用不入成本、部分入库、退货及月末成本差异各有样例。物流标签和代收回款按实际业务另行确认。 | 财务、库存。依赖 2B 的单据及账务边界。 |
| 4 查询、打印与迁移 | 整理待收发、往来余额、采购销售明细、毛利及分仓查询。先对齐已有报表和导出，核对毛利用出库还是发票口径。确认条码、物流标签和开票需求跟踪的打印场景。补客户/供应商双身份、地址、单位、档位、期初未结的映射。 | 报表按仓库、日期、往来方筛选后可追溯原单，金额与库存流水、应收应付及总账一致。代表性标签或凭证可打印。迁移两次重放无重复，期初数量和未结明细逐条对账。 | 财务、库存、ERP 管理员。迁移字段整理可从第 1 批启动，金额验收依赖第 2、3 批。 |

## 3. 单独评估的功能

以下差距已有记录，先由岗位负责人确认是否进入本次补齐范围。确认后为每项补充使用场景、涉及角色、原生能力和验收证据。

| 功能 | 需要确定的业务条件 |
|---|---|
| 调拨订单与智能补货 | 调拨是否必须先申请审批，补货建议是否需要考虑在途、预留、安全库存和替代单位。 |
| 生产组装、独立费用单与全月成本表 | 组装和费用单是否属于日常任务。成本表要按实际估值算法对齐，财务先核对旧系统是否实际使用全月一次加权平均。 |
| 税务开票集成与物流代收 | 明确开票申请跟踪、法定发票签发、物流代收和实际资金到账各自需要的操作。集成类项目按既有首版范围另行确认。 |

## 4. 交付与验收

- 每批交付可操作的本地入口或原生配置、对应的合成测试单和预期结果、配置及操作说明。操作界面统一中文，商品和订单保留中英文核对字段。
- 每批先检查正确流程，再检查权限、原单状态、重复执行及失败恢复。金额、库存或核销涉及的场景要回读原生单据和报表。使用仓库中相应的采购、销售、库存、岗位权限和输出验证脚本，命令及实际结果写入交接文档。
- 本地完成后安排采购、销售、库存和财务岗位验收。涉及真实期初、正式候选构建或发布的项目，继续按现有 M1、A1 的迁移、恢复、回退和发布要求执行。[工作台发布计划](WORKBENCH_RELEASE_PLAN.md) · [首版范围](FIRST_RELEASE_SCOPE.md)

**首个可执行任务**是在隔离测试站用现有五档商品建立取价冲突与含税预览样例，先验证原生能力并记录实际差异，同时完成 1B 的预览核对设计。以同一张单据的预览金额、保存金额和金额差异记录作为首批验收证据。

## 5. 首批执行进度

- **1A 原生取价验证已完成。** 18081 隔离站通过客户和供应商各六个场景。默认档位每件 100 元，往来专价每件 90 元。达到十件门槛时，优先级 10 的规则先于优先级 1，返回每件 75 元。过期后回退为专价。每盒为 50 件时，一盒触发数量规则、返回 3,750 元，无该往来规则时返回盒价 4,900 元。这些为合成试验值。历史价有效窗口、真实规则顺序、精确来源提示、最低售价与人工改价权限仍待完成。
- **1B 保存前含税预览已实现。** 编辑商品、数量、单位、折扣或税费后，工作台在商品明细下调用原生只读计算，给出逐行含税值及整单净额、税费、含税合计。普通交易草稿优先使用预览，运输规则、POS、合并发票等特殊场景保留保存后核对。四张合成报价的预览与保存金额一致。Chrome 已验证数量由两件改为三件时，含税合计从 170.10 元更新为 255.15 元，并以同额保存。扫码、批量录入和业务默认值仍按批次继续验收。
